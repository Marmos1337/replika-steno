# Архитектура «Реплики»

Всё работает на телефоне. В манифесте нет разрешения INTERNET, поэтому приложение физически не может отправить аудио или текст наружу. Единственное разрешение — микрофон (для записи встречи).

## Конвейер

```
аудиофайл (SAF) ─┐
микрофон (AAC) ──┴─► копия в filesDir/recordings/<id>/audio
                         │
                         ▼
1. Декодирование      MediaExtractor + MediaCodec → 16 кГц, моно, float
                         │
                         ▼
2. Диаризация         Silero VAD → фразы по паузам (длинные режутся каждые 12 с)
                      TitaNet-small → голосовой отпечаток (эмбеддинг) каждой фразы
                      кластеризация со средней связью по косинусному расстоянию, порог 0,6
                      → кто говорит когда; число говорящих не задаётся заранее
                      Segments.normalize: обрезка по длительности, склейка соседних фраз
                      одного говорящего (пауза < 600 мс), устранение наложений
                      speaker_1, speaker_2 … — по порядку первого появления
                         │
                         ▼
3. Распознавание      каждая реплика отдельно (длинные режутся в самой тихой точке, ≤ 20 с)
                      GigaAM v3 (русский, с пунктуацией) → если ответ в основном латиницей,
                      та же фраза распознаётся Parakeet TDT-CTC 110M (английский)
                         │
                         ▼
4. Оформление (LLM)   Qwen2.5-0.5B-Instruct, MediaPipe LLM Inference, жадное декодирование
                      получает только текст реплик пачками по 6 строк;
                      TextGuard принимает ответ, только если последовательность слов
                      совпадает с исходной (меняться могут лишь пунктуация и регистр)
                         │
                         ▼
5. Итоги              та же LLM, окна по ~1600 символов с глобальной нумерацией реплик;
                      пункт без ссылки на существующую реплику отбрасывается;
                      исполнитель поручения берётся из говорящего процитированной реплики
                         │
                         ▼
   Recording (JSON в filesDir) → экран расшифровки → экспорт по схеме организаторов
```

Границы времени и speaker_id задаёт только диаризация (шаг 2). LLM не видит времени и говорящих при оформлении и не может их изменить. Исходный текст распознавателя хранится в `Utterance.rawText` и не меняется ни LLM, ни ручной правкой пользователя.

## Экспорт

`TranscriptJson.encode` пишет ровно ключи `speaker_id`, `start_ms`, `end_ms`, `text`, время — целые миллисекунды. Отображаемые имена участников лежат отдельно в `Recording.speakerNames` и в экспорт не попадают. Перед экспортом `TranscriptJson.validate` проверяет `0 <= start_ms < end_ms <= длительность` и формат `speaker_N`.

## Уверенность

Распознаватели в sherpa-onnx не отдают оценку уверенности по словам, поэтому процентов «точности распознавания» приложение не показывает. Настоящая оценка есть у диаризации: косинусная близость голосового отпечатка фразы к центру её кластера (от −1 до 1). Реплики с близостью ниже 0,5 помечаются «говорящий под вопросом».

## Модули

| Пакет | Что внутри |
|---|---|
| `core` | модель данных, декодер аудио, сегменты, `Pipeline`, `TextGuard`, `SummaryParser` |
| `diar` | `VadDiarizer` (sherpa-onnx VAD + эмбеддинги), `Clustering` (чистый Kotlin) |
| `asr` | `SherpaRecognizer` (GigaAM + Parakeet), `ModelAssets` |
| `llm` | `LlmFormatter` (MediaPipe + Qwen) |
| `data` | `RecordingStore` (файлы JSON), `Settings` (DataStore + синхронное зеркало темы) |
| `export` | `TranscriptJson` |
| `ui` | Jetpack Compose: записи, обработка, расшифровка, итоги, «О приложении» |

Обработка идёт в корутине уровня приложения: уход с экрана её не прерывает, «Отменить» останавливает её между фразами (и между пачками LLM). Если процесс был убит во время обработки, при следующем запуске запись помечается «Обработка была прервана» с кнопкой повтора.

## Почему не pyannote

Сначала стояла связка pyannote-segmentation-3.0 + CAM++ из sherpa-onnx. На тестовых диалогах она склеивала соседние реплики разных людей через паузу < 1 с и ошибалась в 3–4 репликах из 8. Схема «VAD → TitaNet-small → своя кластеризация» на тех же файлах дала 8 из 8 и 4 из 4 правильных говорящих, причём одинаково на порогах 0,5–0,7. Подробности в `docs/TESTS.md`.
