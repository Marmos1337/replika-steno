## Метрики

`tools/eval.py <экспорт.json> <эталон.json> --duration-ms N` считает:
- проверку схемы: ровно ключи `transcript` / `speaker_id`, `start_ms`, `end_ms`, `text`; время — целые числа; `0 <= start_ms < end_ms <= длительность`; `speaker_id` вида `speaker_N`;
- WER: нижний регистр, без пунктуации, ё = е;
- долю времени речи с правильным говорящим: оптимальное однозначное сопоставление говорящих гипотезы и эталона, пересечение по времени.

## Точность (экспорт из приложения на эмуляторе, финальная схема диаризации)

JSON выгружен кнопкой «Сохранить JSON» в приложении и забран с устройства (`artifacts/test-results/exports/device_*.json`).

| Файл | Схема | WER | Время с верным говорящим | Говорящих (эталон / найдено) |
|---|---|---|---|---|
| ru_dialog_2voices | ок | 1,2 % | 99,9 % | 2 / 2 |
| en_dialog_2voices | ок | 0,0 % | 99,3 % | 2 / 2 |
| long_mixed_6min | ок | 3,0 % | 98,6 % | 4 / 4 |

Тот же конвейер на Mac через Python-пакет sherpa-onnx (`tools/mac_check.py`, `artifacts/test-results/exports/mac_*.json`): русский 0,0 % / 99,9 %, английский 6,1 % / 98,7 %, смесь 3,0 % / 98,4 %. Разница с устройством — в одной-двух словах на границах фраз.

### Как подбирались параметры

| Вариант диаризации | Русский диалог | Английский | Смесь 6 мин |
|---|---|---|---|
| pyannote-segmentation-3.0 + CAM++, порог 0,5 (первый вариант) | 3–4 реплики из 8 не тому говорящему, соседние реплики склеены | 1 из 4 неверно | не мерили |
| Silero VAD + TitaNet-small, без полей | WER 0 %, 94,8 % | 15,2 %, 86,9 % | 6,2 %, 91,8 % |
| + поля 150 мс | 1,2 %, 98,9 % | 0 %, 93,5 % | 3,5 %, 96,2 % |
| + поля 250 мс | 0 %, 100 % | 9,1 %, 99,4 % | 3,0 %, 98,3 % |
| + поля до 400 мс, не больше половины паузы (итог) | 0 %, 99,9 % | 6,1 %, 98,7 % | 3,0 %, 98,4 % |

Порог кластеризации TitaNet проверен на 0,5, 0,6 и 0,7: разметка не менялась, выбран 0,6. Пороги CAM++ 0,2–0,8 давали либо лишних говорящих, либо одного.

## Скорость

RTF = время до готовой расшифровки / длина аудио (декодирование + диаризация + распознавание). Загрузка моделей в память и LLM-фаза (оформление и итоги, идёт в фоне после показа расшифровки) указаны отдельно.

## Память

Пиковый PSS процесса во время обработки 6-минутного файла (`dumpsys meminfo` раз в секунду): **1583 МБ**. После окончания LLM-модель закрывается сразу, модели распознавания — через 30 с простоя; PSS в простое после этого: **148 МБ** (до этой правки было 1571 МБ).

## Устойчивость

| Сценарий | Ожидание | Результат |
|---|---|---|
| Сеть выключена, импорт нового файла через системный выбор | Работает полностью | ок |

| Обрезанный m4a | Понятная ошибка | «В файле нет звуковой дорожки.» |

| «Отменить» во время обработки | Остановка, без падения, можно запустить снова | ок. Найдены и исправлены две ошибки: статус после отмены не сохранялся (отменённая корутина отменяла и запись), отмена при декодировании маскировалась под «файл повреждён». Если отменить во время загрузки моделей, остановка происходит после её окончания (нативную загрузку нельзя прервать), экран сразу пишет «Останавливаю…» |

| Экспорт JSON | Разбирается стандартным парсером, типы и границы верны | ок для всех трёх файлов (Python `json` + `tools/eval.py`) |
| Ошибок в logcat crash-буфере за все прогоны | 0 | 0 |

## Юнит-тесты

`./gradlew :app:testDebugUnitTest` — 9 тестов, 0 падений: схема экспорта и валидация, нормализация сегментов, нарезка длинных реплик, кластеризация, защита от изменения слов LLM, разбор итогов, «кому/срок» только из сказанного, выбор языка.

## Что не проверено

- Реальный телефон (скорость и память на нём будут другими).
- Живые голоса с шумом и одновременной речью.
- Запись с микрофона: в эмуляторе нет реального микрофона, экран и разрешение проверены, качество записи — нет.
- Записи длиннее 6 минут.
